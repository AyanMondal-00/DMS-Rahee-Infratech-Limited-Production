2. EXECUTIVE SUMMARY & SYSTEM PURPOSE
================================================================================

The Enterprise Document Management System (EDMS) is a secure, high-throughput, 
multi-tenant document governance platform engineered specifically for the 
engineering, infrastructural, and administrative operations of:

  1. RAHEE INFRATECH LIMITED (Company 1 / Contractor)
  2. IRCON INTERNATIONAL LIMITED (Company 2 / Authority & Client)
  3. BIKRAMSHILA INFRASTRUCTURE PROJECT (Joint Central Repository)

Key Objectives of the Platform:
--------------------------------
1. Centralized Blueprints & CAD Repository:
   A single, unified, structured digital vault for all civil, structural, 
   track, architectural, and mechanical blueprints, contract documents, 
   inspection certificates, and quality assurance logs.

2. Strict Multi-Tenant Isolation with Universal Cross-Company Preview:
   Complete tenant security and upload control per company branch under the 
   central "Bikramshila" root directory, paired with open cross-company viewing 
   and downloading rights for all authorized stakeholders.

3. Granular Role-Based Access Control (RBAC):
   Deterministic permissions mapping user designations (Super Admin, Admin, 
   Execution Control, Manager, Reviewer, Viewer) to specific operational capabilities.

4. High-Capacity Engineering Storage:
   Direct disk-backed streaming storage capable of handling heavy CAD models, 
   multi-page raster blueprints, and high-resolution engineering reports with 
   generous 500MB payload limits and zero artificial file size caps.

5. In-Browser Multi-Format Document Previews:
   Zero-install in-browser rendering for PDF, Microsoft Word, Microsoft Excel, 
   Microsoft PowerPoint, 2D/3D CAD Blueprints, and high-resolution images.

6. Immutable Compliance & Audit Trail:
   Continuous append-only logging of every user login, document upload, 
   view, preview, download, modification, archival, restoration, and deletion.

--------------

-------------------------------

  attempts occur on an account, the account is temporarily locked for 15 minutes.

  password from the Users Management console.

---------------
- Click your Profile / Name badge at the top-right corner of the navigation bar 
  and select "Sign Out".
- Your active session token is immediately cleared from browser memory.

10. BIKRAMSHILA DOCUMENT DRIVE & DIRECTORY MANAGEMENT
================================================================================

The Central Documents page (/documents) functions identically to modern cloud 
drives and Windows Explorer:

10.1 Folder Traversal & Breadcrumb Navigation
--------------------------------------------
- Bikramshila Drive Root: Clicking the root drive displays the main company 
  branches (`RAHEE` and `IRCON`).
- Explorer-Style Path Bar: The top path bar displays the exact directory hierarchy:
  Example: Bikramshila Drive > RAHEE > Engineering & Drawings > Track Blueprints
- History Navigation: Use the "Back", "Forward", and "Up to Parent" buttons to 
  navigate between directories without losing your search context.
- Double-Click Traversal: Click any folder card in the view to immediately 
  enter that subdirectory.

10.2 Creating Subfolders
------------------------
1. Navigate to the desired parent directory (e.g. `Bikramshila/RAHEE`).
2. Click the "+ New Folder" button at the top-right of the directory view.
3. Enter the Folder Name (e.g., "Quality Inspection Reports Q4").
4. Optional: Enter a description.
5. Optional: Toggle "Operational Folder" if this folder is exempt from auto-archival.
6. Click "Create Folder". The folder is immediately available for uploads.
* Note: Creating folders is permitted for Rahul Dey, Om Jha, and Super Admins.

10.3 Renaming & Modifying Folder Properties
-------------------------------------------
1. Locate the folder card or navigate inside the folder.
2. Click the "Rename Folder" button or settings icon.
3. Update the folder title or description and click "Save Changes".

10.4 Granular Folder Access Control & Permission Rules
------------------------------------------------------
1. Click the "Access Control / Permissions" icon on any folder.
2. Add specific role-based or user-specific permission rules:
   - Full Control (Upload, Edit, Preview, Download)
   - Read Only (Preview & Download)
3. Check "Apply recursively to all subfolders" to inherit permissions downward.
4. Click "Save Permissions".

10.5 Search & Multi-Parametric Filtering
----------------------------------------
- Keyword Search: Type any keyword to filter documents by title or filename in real time.
- Date Range Filters: Select "From Date" and "To Date" to isolate documents uploaded 
  during specific project periods.
- File Format Dropdown: Filter by PDF, CAD, Word, Excel, PowerPoint, or Images.
- Company Filter: Switch between Rahee Infratech, Ircon International, or All.

11. DOCUMENT INGESTION & HIGH-SPEED UPLOADING
================================================================================

11.1 Authorized Uploaders Matrix
--------------------------------
To maintain strict data integrity, document uploading is permitted exclusively to:
- Rahee Infratech: Rahul Dey (Admin) and Somnath Mondal (Execution Control).
- Ircon International: Om Jha (Admin).
* For all Viewer and Manager accounts, upload actions are disabled.

11.2 Step-by-Step Document Upload Procedure
-------------------------------------------
1. Navigate to "Upload Document" in the left sidebar (/documents/upload).
2. Step 1 - Select Document File Format:
   Select the required file category from the dropdown:
   - PDF Documents (.pdf)
   - CAD Drawings / 3D Models (.dwg, .dxf, .stl, .obj, .step, .stp, .iges)
   - Microsoft Word (.doc, .docx)
   - Microsoft Excel (.xls, .xlsx)
   - Microsoft PowerPoint (.ppt, .pptx)
   - Images (.jpg, .jpeg, .png, .webp, .svg)
3. Step 2 - Select Destination Folder:
   Use the tree selector to choose the exact branch folder (e.g., `Bikramshila/RAHEE/Engineering`).
4. Step 3 - Select or Drop Document File(s):
   - Click the dropzone to open the Windows File Explorer (pre-filtered for your chosen format).
   - Or drag and drop single or multiple files directly onto the dropzone.
5. Review & Edit Titles in Staging Area:
   - Each staged file displays its name, size, and an editable Document Title field.
   - Edit the document title if a formal naming convention is required.
   - Remove individual files or click "Add More Files" to add additional files.
6. Click "Upload All Documents":
   - The animated Upload Modal appears, tracking real-time data transfer in Megabytes (MB) 
     and percentage progress.
   - Cryptographic SHA-256 signatures are calculated and verified.
   - Upon completion, the system redirects you directly to the uploaded file.

11.3 High-Capacity Performance & 500MB Support
----------------------------------------------
- File Size Capacity: The upload pipeline supports files up to 500MB+ per file.
- Direct Disk Streaming: Files stream directly from client to server disk storage 
  without intermediate memory bottlenecks.
- Batch Ingestion: Multiple drawings can be uploaded simultaneously in a single transaction.

11.4 Anti-Malware & Extension Protection
----------------------------------------
- Prohibited Extensions: Executables and scripts (.exe, .bat, .cmd, .sh, .vbs, .msi, .dll) 
  are rejected immediately at the browser boundary and backend validator.

21. SYSTEM INSTALLATION, STARTUP & MAINTENANCE GUIDE
================================================================================

21.1 Infrastructure Prerequisites
---------------------------------
- Node.js: Version 18.0.0 or higher.
- MySQL Server: Version 8.0 or higher (or MySQL 5.7+).
- Operating System: Windows Server / Windows 10/11, Linux (Ubuntu/Debian/RHEL), or macOS.

21.2 Database Initialization & Schema Seeding
---------------------------------------------
1. Start your MySQL Server service.
2. Import the master schema and initial seed data:
   Using MySQL Command Line:
   ```cmd
   mysql -u root -p < backend/schema.sql
   ```
   Or open `backend/schema.sql` in MySQL Workbench / phpMyAdmin and execute the script.
3. Database `enterprise_dms` is created with all 13 tables, roles, permissions, folders, 
   and verified default user accounts.

21.3 Backend Service Startup
----------------------------
1. Open PowerShell or Command Prompt.
2. Navigate to the backend directory:
   ```cmd
   cd backend
   ```
3. Install dependencies (first time only):
   ```cmd
   npm install
   ```
4. Start the backend REST and WebSocket server:
   ```cmd
   npm start
   ```
   - Server runs on: http://localhost:5000
   - Health check endpoint: http://localhost:5000/api/health (returns `{"status":"UP"}`)

21.4 Frontend Web Application Startup
-------------------------------------
1. Open a new PowerShell or Command Prompt terminal.
2. Navigate to the frontend directory:
   ```cmd
   cd frontend
   ```
3. Install frontend dependencies (first time only):
   ```cmd
   npm install
   ```
4. Start the Vite development web server:
   ```cmd
   npm run dev
   ```
   - Web application URL: http://localhost:5173

21.5 Network Binding & Dynamic IP Resolution
--------------------------------------------
- The frontend includes a dynamic host resolver (`frontend/src/services/api.js`).
- If accessed from another computer on the local area network (LAN) via `http://192.168.X.X:5173`, 
  the application automatically binds API requests to `http://192.168.X.X:5000` with zero CORS issues.

22. COMPLETE REST API REFERENCE
================================================================================

Authentication Endpoints:
-------------------------
- POST /api/auth/login
  Body: { "email": "user@rahee.com", "password": "password" }
  Returns: { "success": true, "token": "<JWT_TOKEN>", "user": { ... } }

- GET /api/auth/me
  Headers: Authorization: Bearer <JWT_TOKEN>
  Returns: Active user profile, designation, organization, and granted permissions.

Document Endpoints:
-------------------
- GET /api/documents
  Query Params: ?folder_id=2&document_type=CAD&search=Track&limit=30&offset=0
  Returns: Array of document metadata objects and total count.

- POST /api/documents (Multipart / Form-Data)
  Payload: files (binary), folder_id, document_type, category, files_metadata (JSON string)
  Returns: Created document records and assigned IDs.

- GET /api/documents/:id
  Returns: Full metadata, folder hierarchy trail, and version history.

- GET /api/documents/:id/preview
  Returns: Streamed binary data or rendered HTML preview.

- GET /api/documents/:id/download
  Returns: Streamed original binary file attachment with original filename header.

- POST /api/documents/:id/archive (Super Admin Only)
  Returns: Success confirmation and moved status.

- POST /api/documents/:id/restore (Super Admin Only)
  Returns: Restored active status in original folder.

- DELETE /api/documents/:id (Super Admin Only)
  Returns: Moves document to Recycle Bin.

Folder Endpoints:
-----------------
- GET /api/folders
  Returns: Complete Bikramshila folder tree with document counts.

- POST /api/folders
  Body: { "name": "Folder Name", "parent_id": 2, "description": "..." }
  Returns: Created folder object.

- PUT /api/folders/:id
  Body: { "name": "New Name", "description": "..." }
  Returns: Updated folder metadata.

- GET /api/folders/:id/permissions
  Returns: Granted role and user permission rules for this folder.

- POST /api/folders/:id/permissions
  Body: { "permissions": [ ... ], "apply_to_subfolders": true }
  Returns: Updated permission confirmation.

Recycle Bin Endpoints (Super Admin Only):
-----------------------------------------
- GET /api/recycle-bin/items
  Returns: List of deleted folders and documents in the recovery vault.

- POST /api/recycle-bin/restore/document/:id
  Returns: Restores file to its original target folder path.

- POST /api/recycle-bin/restore/folder/:id
  Returns: Restores folder and its subfolders to original hierarchy.

- POST /api/recycle-bin/restore-all
  Returns: Restores all items in bin.

- DELETE /api/recycle-bin/permanent/document/:id
  Returns: Permanently erases file and purges disk storage.

- DELETE /api/recycle-bin/empty
  Returns: Permanently empties recovery vault.

User & Report Endpoints:
------------------------
- GET /api/users - List system users (All Users).
- POST /api/users - Create new user (Super Admin Only).
- PUT /api/users/:id/reset-password - Reset user password (Super Admin Only).
- PATCH /api/users/:id/status - Toggle user active/disabled status (Super Admin Only).
- GET /api/reports/dashboard - Real-time metrics, storage breakdown, and chart data.
- GET /api/audit-logs - Immutable system audit logs with search and action filters.
- GET /api/notifications/emails - Delivery logs for all system notifications.

    and automated query retries that recover instantly without dropping user sessions.
